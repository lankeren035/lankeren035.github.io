图_13Agent与工具运行时

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

所属模块： M4 Agent 与工具运行时。总图与详图使用相同模块编号；画布右侧也包含以下读图说明。

运行时

  • MODEL 与 System Prompt 创建外层 Agent；绑定天气工具和请求专属知识工具。

流程

  • MODEL 可直接回复，或发出 tool call；结果作为 ToolMessage 回到模型。
  • 知识工具申请 ctx 一次额度，运行 RAG，并保存 Trace/恢复快照。
  • service 对 HITL 结果改为澄清提示。

约束

  • 知识调用次数有硬额度；收到知识结果后不再调工具主要由提示词约束。
  • FAST/GRADE 分别用于笔记/规划/改写与评分，不是外层 Agent 的重复回路。

源码对应

  • backend/chat/runtime.py：create_agent_for_request()
  • backend/tools/knowledge.py：make_search_knowledge_base()
  • backend/tools/weather.py：get_current_weather()

图_12文档删除流程

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

所属模块： M6 文档管理。总图与详图使用相同模块编号；画布右侧也包含以下读图说明。

M6 组成

  • 列表聚合 Milvus 叶子记录；上传衔接 M7 索引；删除清理多种存储。
  • 同步在请求内完成；异步返回 job_id，进度由内存 JobManager 提供。
  • 上传细节见图 03，下方展开删除分支。

清理顺序

  • Milvus L3 → PG L1/L2 commit → Redis 父块缓存删除。
  • BM25 统计由 Milvus 自动维护；没有独立重建任务。

边界

  • 本地原文、聊天历史和已保存 Trace 保留。
  • transactionally 是函数名，不代表跨库事务。
  • 部分失败无自动回滚；Redis 异常可能被忽略。

源码对应

  • backend/api/routes/documents.py：delete_document_async()
  • backend/api/routes/documents.py：_process_delete_job()
  • backend/api/resources.py：delete_document_transactionally()
  • backend/indexing/parent_chunk_store.py：delete_by_filename()
  • backend/jobs/upload_jobs.py：UploadJobManager()

图_11鉴权与会话管理

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

所属模块： M2 接口与鉴权；会话操作属于 M3。总图与详图使用相同模块编号；画布右侧也包含以下读图说明。

接口层组成

  • app.py 装配环境、启动建表、中间件、业务路由和可选静态托管。
  • router 注册 auth/sessions/chat/documents；Pydantic 与 Depends 承担校验和依赖注入。

身份

  • 注册/登录签发 JWT；后续按 sub 查询当前 DB User。
  • 管理员权限读取 DB role，不直接信任 JWT role。

会话

  • 前端新建 session_id 后，第一次聊天 save 才建 PG 会话。
  • 所有会话查询用当前用户身份限定；删除级联清消息和缓存。

边界

  • 没有创建会话 API、token 刷新表或服务器 logout 状态。
  • 会话隔离不意味着每人一套知识库。

源码对应

  • backend/infra/auth.py：get_current_user()
  • backend/infra/auth.py：resolve_role()
  • backend/api/routes/auth.py
  • backend/api/routes/sessions.py
  • backend/chat/storage.py：delete_session()
  • frontend/src/stores/chat.ts
  • frontend/src/stores/auth.ts
