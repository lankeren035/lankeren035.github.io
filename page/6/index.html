图_2用户问答流程

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： M3 模块主图。

输入与输出

  • 输入为 message、session_id 和登录身份；输出为回答、Trace 或澄清请求。

流程

  • 先加载会话和 metadata，创建本轮 ctx，保存用户消息。
  • 有有效恢复快照则定向恢复 RAG；其余进入 Agent。
  • 普通回答、天气与知识结果最终回到对话编排。

边界

  • ctx 是请求状态；笔记和 pending_hitl 是跨轮持久状态。
  • 同步保存后返回；SSE 的 DONE 先于最终保存。

  • backend/chat/service.py：_build_context_messages()

视图归属： 系统总览。

如何读总图

  • 系统分为五层、八个职责模块 M1～M8。
  • 模块卡片只链接一张模块主图；子专题从对应主图继续进入。
  • 灰色依赖区是第三方服务，不是额外业务模块。
  • 分层表示职责，M3/M6 也可直接访问 M8，不是强制逐层调用。

两条主链

  • 问答：M1 → M2 → M3 → M4 → M5；M8 承担历史与证据存储。
  • 入库：M1 → M2 → M6 → M7 → M8。

图_15文档索引模块设计

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。

视图类型： M7 文档索引模块主图。上级为 [[图_1项目设计|系统总图]]。

模块边界

  • 输入是 M6 已保存的 file_path 与 filename；鉴权、文件保存、同名清理和 job 属于 M6。
  • M7 提供解析、三级分块、父块存取、叶子向量化与写入组件；原版没有独立 IndexingService。

真实调用

  • DocumentLoader 按格式读取，再清洗文本、补充来源 metadata 并三级分块。
  • M6 在 documents.py 中拆出 parent_docs / leaf_docs，先调用父块存储，再调用向量写入。
  • MilvusWriter 初始化集合，按批调用 EmbeddingService，再组装字段并 insert。

存储与约束

  • L1/L2 写入 PG，逐项缓存 Redis；L3 写入 Milvus。
  • 本地模型只生成 dense；BM25 sparse 由 Milvus 的服务端函数生成。
  • 父块 commit 后才开始叶子写入；中途失败没有统一跨库回滚。

关联视图

  • 图 03 是上传任务的完整业务流程；图 08 是三级分块与跨库关联的数据契约。

图_10SSE流式时序

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： M3 SSE 流式专题。

组成

  • Agent worker、ctx 队列、SSE service 和前端读取器共同传递事件。

流程

  • 进度由 ctx 线程安全入队；worker 把文本或错误入队。
  • service 发送 content/rag_step/trace/hitl_request 等 JSON 事件。
  • 内部 None 表示 worker 结束；SSE DONE 是另一种哨兵。

完成时序

  • DONE 后才更新笔记并保存，前端继续读至 EOF。
  • 用户停止只是取消路径，不保证外部调用立刻停止或 AI 已保存。

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

所属模块： M1 前端交互。总图与详图使用相同模块编号；画布右侧也包含以下读图说明。

组件与状态

  • Vue 组件展示登录、聊天、历史、文档与证据；Pinia 四个 store 持有前端状态。

问答流程

  • 登录 token → Bearer 请求；本地 session_id → 提交 message。
  • 按 SSE 事件更新发起会话的消息、进度、Trace 和 HITL 提示。
  • 切换会话不改变原请求数组；停止使用 AbortController。

文档与边界

  • 管理员上传后轮询 job，完成再刷新文档列表。
  • 上传轮询在面板关闭后继续；删除轮询在组件卸载时停止。
  • 前端不做 RAG 路由，也不承担服务器权限判断。

源码对应

  • frontend/src/App.vue
  • frontend/src/stores/chat.ts
  • frontend/src/stores/documents.ts
