图_7数据库ER关系

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： M8 PostgreSQL ER 专题。

实体与属性

  • 四个矩形分别表示四张真实 PG 表；28 个椭圆逐一对应全部属性。
  • 主键属性加下划线，外键属性标记 FK；不展示类型/长度字段表。

联系与基数

  • 用户 1:N 会话；会话 1:N 消息。
  • 双线表示每个会话必须属于用户、每条消息必须属于会话。
  • 普通单线一侧允许没有子记录。

独立实体

  • ParentChunk 属于共享知识库，没有 User/Session 外键。
  • parent/root 是业务引用，不能虚构成 PG 自关联 FK。

图_6数据存储与状态

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： M8 模块主图。

数据责任

  • PG 是用户、会话、消息和父块的持久存储；Milvus 保存 L3。
  • 原文在本地；Redis 仅缓存历史、列表和父块。

状态生命周期

  • metadata 里的笔记和 pending_hitl 跨轮保存。
  • ctx 与 RAGState 每请求/每次图调用新建。
  • JobManager 是进程内状态；浏览器视图不是服务端持久状态。

一致性

  • 会话先 PG commit 再更新缓存；父块会先写缓存再 commit。
  • 没有跨 PG、Redis、Milvus 的统一事务。

源码对应

  • backend/db/models.py
  • backend/infra/cache.py：RedisCache()
  • backend/chat/storage.py：load_with_meta()
  • backend/indexing/parent_chunk_store.py：ParentChunkStore()
  • backend/chat/request_context.py：ChatRequestContext()
  • backend/jobs/upload_jobs.py：UploadJobManager()
  • backend/api/resources.py

图_4检索与Evidence构建

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： M5 检索专题。

输入与输出

  • 输入 query 与 top_k；输出 docs 和检索 meta，尚未生成答案。

流程

  • BGE query 编码后，Milvus 对 L3 执行 dense + BM25 + RRF。
  • 候选经过两轮父块合并；Redis 优先、PG 回取父文本。
  • 精排或回退排序先截 top_k，再过滤最低分，不回填。

异常

  • Hybrid 链异常会重试 dense；精排失败回退原分排序。
  • 最终可能少于 top_k 或为空；空证据由 M5 决策。

图_3文档入库流程

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： 跨模块业务流程（M6 → M7 → M8）。

组成

  • M6 负责上传接口、原文保存、job 和同名清理；M7 负责解析、分块、向量化与写入。

流程

  • 异步上传先保存新文件，再在后台清理同名旧索引。
  • 解析后按页/章节切成 L1/L2/L3。先写父块，再处理叶子块。
  • L3 本地生成 dense，BM25 sparse 由 Milvus 服务端生成。

边界

  • 任务只在内存；失败不自动跨库回滚。
  • 同步上传先清旧索引再写文件，没有 job。

源码对应

  • backend/api/routes/documents.py：upload_document_async()
  • backend/api/routes/documents.py：_process_upload_job()
  • backend/api/routes/documents.py：upload_document()
  • backend/indexing/document_loader.py：DocumentLoader()
  • backend/indexing/html_processor.py
  • backend/indexing/milvus_writer.py：write_documents()
  • backend/indexing/parent_chunk_store.py：upsert_documents()
