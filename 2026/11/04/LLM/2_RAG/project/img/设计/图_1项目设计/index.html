图_1项目设计

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

视图归属： 系统总览。

如何读总图

  • 系统分为五层、八个职责模块 M1～M8。
  • 模块卡片只链接一张模块主图；子专题从对应主图继续进入。
  • 灰色依赖区是第三方服务，不是额外业务模块。
  • 分层表示职责，M3/M6 也可直接访问 M8，不是强制逐层调用。

两条主链

  • 问答：M1 → M2 → M3 → M4 → M5；M8 承担历史与证据存储。
  • 入库：M1 → M2 → M6 → M7 → M8。
  • 跨轮 HITL 和 SSE 归 M3 编排；前端 M1 负责消费事件和展示。

源码对应

  • backend/app.py：create_app()
  • backend/api/router.py
  • backend/chat/service.py：chat_with_agent()
  • backend/chat/runtime.py：create_agent_for_request()
  • backend/api/resources.py
  • docker-compose.prod.yml

本次层级修正

导航规则

  • 每个模块框只链接一张模块主图；模块主图再链接自己的专题。
  • M3：图 02 → HITL 图 09 / SSE 图 10；M5：图 05 → 检索图 04；M8：图 06 → ER 图 07。
  • M7 主图新增为图 15；图 03 / 08 作为跨模块协作视图保留在连接线上。

依赖与数据流

  • M5 → M8：查询 Milvus，回取 Redis/PG 父块；M7 → M8：写入父块、叶子与向量。
  • M4 通过 M5 获取知识；有效 HITL 恢复可由 M3 直接进入 M5。
  • L4 分层外框不再承担到 M8 的聚合箭头；外部依赖按卡片注明的调用方使用。
