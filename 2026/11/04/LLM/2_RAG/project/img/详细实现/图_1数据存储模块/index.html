读图方式

  1. 蓝底是文件，紫底是类，灰底是函数；框宽按文字自适应，标题与分步文本分开。
  2. 每个函数 / 类有唯一编号，例如 F01 / C01；步骤末尾 〔→ F07〕 表示调用或依赖对应编号。P 编号表示文件；P02:3 精确定位到 P02 文件的第 3 步，F04:2 定位函数 F04 的第 2 步。
  3. 只有相邻、能在文件内短距离连接且不穿越文字 / 其他函数框的关系画曲线。其余保留编号引用。重复使用的公共助手不再扇出多条长线。
  4. 编号仅用于查找，不表示全局执行顺序；每个框里的 1、2、3 才是该框的执行步骤。总图另有问答与入库主链。

文件与函数索引

P01 · backend/env.py

统一加载项目根目录环境变量。

  • F01 load_env()（源码 10 行）：只加载一次 .env。

P02 · backend/infra/database.py

  • F02 _clean_nul_chars()（源码 25 行）：递归清洗字符串和容器参数。
  • F03 before_cursor_execute()（源码 60 行）：在底层 SQL 执行前净化绑定参数。

P03 · backend/infra/cache.py

统一 Redis JSON 缓存与错误降级。

  • F05 RedisCache.__init__()（源码 9 行）：保存连接配置与默认缓存参数。
  • F06 RedisCache._get_client()（源码 15 行）：按需创建并复用 Redis 客户端。

  • F09 RedisCache.set_json()（源码 32 行）：序列化对象并带过期时间写入。
  • F10 RedisCache.delete()（源码 39 行）：删除一个缓存键。
  • F11 RedisCache.delete_pattern()（源码 45 行）：按模式批量删除缓存键。
  • C01 RedisCache：保存连接配置并提供缓存接口。

P04 · backend/db/models.py

向同一个 Base.metadata 注册四张 ORM 表。

  • C08 ParentChunkStore：持久化 L1 / L2，供 Auto-Merging 取全文。
