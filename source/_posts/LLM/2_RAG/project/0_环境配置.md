## 1. 环境安装
```
python -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -e .
```
## 2. 配置文件
- 在`.env`中填好对应的api key
1. llm api key
2. JWT 直接生成：
```shell
openssl rand -hex 32
```
将得到的key放到`JWT_SECRET_KEY`，这作为服务器长期保存的密钥，后面每个用户登录时也会拿到自己的凭证。

## 3. 启动相关服务
```shell
docker compose up -d
docker compose ps
```
- 可能出现的问题：之前已经启用过服务导致端口冲突。

## 4. 编译前端代码
- 首次运行或前端代码修改后
```shell
cd frontend

# 安装前端依赖
npm install

# 编译构建静态包
npm run build
```
构建产物会自动保存在 `frontend/dist/` 中

## 5. 启动应用

```shell
python -m uvicorn backend.app:app --host 0.0.0.0 --port 8000 --reload
```
浏览器访问：

- 前端页面：`http://127.0.0.1:8000/` （后端静态托管编译后的 `frontend/dist` 资源）
- API 文档：`http://127.0.0.1:8000/docs`

## 6. 前端开发与调试
前端基于 Vite + Vue 3 开发。若需要进行前端代码开发与调试：

```shell
cd frontend

# 1. 启动本地开发服务（运行于 http://localhost:3000，内置反向代理至 FastAPI 后端 8000 端口）
npm run dev

# 2. 编译生产包（构建结果将输出至 frontend/dist/ 目录中，供后端静态托管）
npm run build
```
## 7. 测试
### 7.1 测试RAG 流程
- 提问：你知道 3DGS 吗
1. 第一次报 `response_format unavailable`，说明 DeepSeek 不兼容原项目默认的 OpenAI Structured Output。
新建目录和文件：`backend/llm/__init__.py`
新建`backend/llm/structured_output.py`：
```python
import os

def with_structured_output(model, schema):
    compat = (os.getenv("LLM_API_COMPAT") or "").strip().lower()

    if compat == "deepseek":
        return model.with_structured_output(
            schema,
            method="function_calling",
            extra_body={"thinking": {"type": "disabled"}},
        )

    return model.with_structured_output(schema)
```
修改 `.env`：
```
LLM_API_COMPAT=deepseek
```
修改 `backend/rag/pipeline.py` 与`backend/rag/utils.py` , 把
```python
model.with_structured_output(RewritePlan)
```
改成：
```python
with_structured_output(model, RewritePlan)
```
上述调用函数一共三处，类似改。记得开头导包：
```python
from backend.llm.structured_output import with_structured_output
```

- 再测试后不再报错，RAG 正常完成检索，输出“知识库没有 3DGS 资料”，说明 DeepSeek 兼容问题已解决。
