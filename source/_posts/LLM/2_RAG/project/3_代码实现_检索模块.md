# 1. 模块设计
## 1.1 模块定位
- 已解决：
	- 存储结构
	- 文档入库
- 当前：文档入库后可以进行**检索**了。
---
## 1.2 检索流程设计

```text
                    用户 Query
                        ↓
                    BGE-M3
                        ↓
                dense_embedding
                        ↓
              Milvus Hybrid Search
                ↙             ↘
        Dense Retrieval     BM25 Retrieval
                ↘             ↙
                     RRF
                      ↓
              candidate_k 个 L3
                      ↓
                 Auto-Merging
                 L3 → L2 → L1
                      ↓
                    Rerank
                      ↓
                  Score Filter
                      ↓
                    TopK
                      ↓
                  Evidence
```
- 检索时先将用户 Query 通过 BGE-M3 转换为 Dense Embedding，在 Milvus 中只召回粒度最细的 L3 Chunk，并同时执行 Dense 语义检索和 BM25 关键词检索，再通过 RRF 融合两路结果得到候选集。为了避免 L3 文本过碎，候选结果会根据 `parent_chunk_id` 执行 Auto-Merging：同一 L2 下命中多个 L3 时合并回 L2，同一 L1 下命中多个 L2 时继续合并回 L1；之后对候选结果进行 Rerank 和最低分数过滤，最终选出 TopK 作为提供给 LLM 的 Evidence。如果 Hybrid Retrieval 失败，则自动降级为 Dense Retrieval。
---

## 1.3 文件结构设计

#### `backend/rag/`

- `utils.py`：知识库检索公共能力。
    - `retrieve_documents()`：检索主入口，完成 Hybrid Retrieval、Auto-Merging、Rerank 和过滤。
    - `resolve_candidate_k()`：计算 Milvus 第一阶段召回的候选数量。
    - `_auto_merge_candidates()`：执行 L3 → L2 → L1 Auto-Merging。
    - `_rerank_documents()`：对候选 Chunk 进行精排。
    - `dedupe_documents()`：按照 `chunk_id` 对文档去重。
    - `retrieval_trace_fields()`：提取检索过程中的 Trace 信息。
    - `rewrite_query_once()`：执行一次 Step-back 或 HyDE 查询重写。

### 2.1.2 检索入口

1. `resolve_candidate_k`: 先根据top_k（最终保留多少条）计算第一阶段应该从 Milvus 召回多少个候选 L3 Chunk；
2. 然后根据用户 Query 得到 Dense Embedding，并设置过滤条件只检索 L3。
3. 拿到 Query Embedding 后优先调用 `MilvusStore.hybrid_retrieve()`，执行 Dense + BM25 + RRF 混合检索；
4. 如果 Hybrid Retrieval 发生异常，则自动调用 `MilvusStore.dense_retrieve()` 降级为纯 Dense Retrieval。
5. `_finalize_retrieval()`：召回完成后统一进入结果统一后处理：Auto-Merging、Rerank、分数过滤和 TopK 截断。

```python
def retrieve_documents(

) -> Dict[str, Any]:

                    LEAF_RETRIEVE_LEVEL,
                "recall_count": 0,

                "rerank_enabled": RERANK_ENABLED,
                "rerank_applied": False,
                "rerank_model": RERANK_MODEL,
                "rerank_endpoint":
                    _get_rerank_endpoint(),
                "rerank_error":
                    "embedding_failed",
                "rerank_timeout_seconds":
                    RERANK_TIMEOUT_SECONDS,
                "rerank_min_score":
                    RERANK_MIN_SCORE,
                "post_rerank_count": 0,
                "post_threshold_count": 0,
                "retrieval_empty": True,
            },
        }

            )

                query=query,
                retrieved=retrieved,
                top_k=top_k,
                retrieval_mode="dense_fallback",
                candidate_k=candidate_k,

                "meta": {
                    "retrieval_mode": "failed",
```

#### 1）计算初步侯选数量
- 控制从向量数据库提取多少个L3，优先读取 `RETRIEVAL_CANDIDATE_K`，否则使用 `top_k × multiplier`。其中top_k是最终希望检索出多少条。

```python
def resolve_candidate_k(top_k: int) -> Tuple[int, Dict[str, Any]]:
    """解析 Milvus 候选池大小；RETRIEVAL_CANDIDATE_K 优先，否则 top_k × multiplier。"""
    if _RETRIEVAL_CANDIDATE_K_RAW:
        try:
            candidate_k = max(int(_RETRIEVAL_CANDIDATE_K_RAW), top_k)
        except ValueError:# 配置错误则退回 multiplier
            candidate_k = max(top_k * RETRIEVAL_CANDIDATE_MULTIPLIER, top_k)
            return candidate_k, {
                "candidate_k_source": "multiplier",
                "retrieval_candidate_multiplier": RETRIEVAL_CANDIDATE_MULTIPLIER,
                "candidate_k_config_error": "invalid RETRIEVAL_CANDIDATE_K",
            }
        return candidate_k, {
            "candidate_k_source": "env",
            "retrieval_candidate_multiplier": RETRIEVAL_CANDIDATE_MULTIPLIER,
        }
    # 2. 默认使用 top_k × multiplier
    candidate_k = max(top_k * RETRIEVAL_CANDIDATE_MULTIPLIER, top_k)
    return candidate_k, {
        "candidate_k_source": "multiplier",
        "retrieval_candidate_multiplier": RETRIEVAL_CANDIDATE_MULTIPLIER,
    }
```

#### 2）检索结果统一后处理

- 对第一阶段召回结果（dense或者混合召回）做统一后处理，主要包含：
1. `_auto_merge_candidates()`：先对召回的 L3 Chunk 执行 Auto-Merging，根据父子关系尝试完成 `L3 → L2 → L1` 合并，避免最终 Evidence 过于碎片化。
2. `_rerank_documents()`：将 Auto-Merging 后的候选文本和 Query 一起送入 Rerank，对候选结果重新计算相关度并排序；如果未配置 Rerank 或调用失败，则保留原始检索分数排序。
3. `_meets_rerank_min_score()`：根据 `RERANK_MIN_SCORE` 对低相关度候选进行过滤。
4. `top_k`：Rerank 阶段最多保留 `top_k` 条候选，因此最终输出的 Evidence 数量不会超过 `top_k`。
5. 最后统一生成 `meta`，记录本次检索的 `retrieval_mode`、召回数量、Auto-Merging 情况、Rerank 情况以及最终剩余 Evidence 数量。

```python

def _finalize_retrieval(
    query: str,
    retrieved: List[dict],
    top_k: int,
    retrieval_mode: str,
    candidate_k: int,
    candidate_config: Dict[str, Any],
) -> Dict[str, Any]:
    """生产流水线：召回候选 → Auto-merge → Rerank（top_k）→ 阈值过滤。"""
    # 1. L3 → L2 → L1 Auto-Merging
    candidates, merge_meta = _auto_merge_candidates(retrieved)
    # 2. 对合并后的候选进行 Rerank
    reranked_docs, rerank_meta = _rerank_documents(query=query, docs=candidates, top_k=top_k)
    post_rerank_count = len(reranked_docs)
    # 3. 根据最低相关度阈值过滤
    final_docs = [d for d in reranked_docs if _meets_rerank_min_score(d)]
    # 4. 保存整个检索过程的 Meta
    meta = {
        **rerank_meta,
        **merge_meta,
        **candidate_config,
        "retrieval_mode": retrieval_mode,
        "retrieval_pipeline": "recall_merge_rerank",
        "candidate_k": candidate_k,
        "retrieval_top_k": top_k,
        "leaf_retrieve_level": LEAF_RETRIEVE_LEVEL,
        "recall_count": len(retrieved),
        "rerank_min_score": RERANK_MIN_SCORE,
        "post_rerank_count": post_rerank_count,
        "post_threshold_count": len(final_docs),
        "retrieval_empty": len(final_docs) == 0,
    }
    return {"docs": final_docs, "meta": meta}
```

##### 2-1）Auto-Merging

- `_auto_merge_candidates()`连续执行两次父级合并，实现 `L3 → L2 → L1`。

```python

def _empty_merge_meta() -> Dict[str, Any]:
    return {
        "auto_merge_enabled": AUTO_MERGE_ENABLED,
        "auto_merge_applied": False,
        "auto_merge_threshold": AUTO_MERGE_THRESHOLD,
        "auto_merge_replaced_chunks": 0,
        "auto_merge_steps": 0,
        "post_merge_candidate_count": 0,
    }


def _auto_merge_candidates(docs: List[dict]) -> Tuple[List[dict], Dict[str, Any]]:
    """在完整召回候选上执行 L3→L2→L1 合并；不改变顺序，精排由后续步骤负责。"""
    meta = _empty_merge_meta()
    meta["post_merge_candidate_count"] = len(docs)
    # 没有开启 Auto-Merging 时直接返回
    if not AUTO_MERGE_ENABLED or not docs:
        return docs, meta

    # 1. L3 → L2
    merged_docs, merged_count_l3_l2 = _merge_to_parent_level(docs, threshold=AUTO_MERGE_THRESHOLD)
    # 2. L2 → L1
    merged_docs, merged_count_l2_l1 = _merge_to_parent_level(merged_docs, threshold=AUTO_MERGE_THRESHOLD)

    replaced_count = merged_count_l3_l2 + merged_count_l2_l1
    meta.update({
        "auto_merge_applied": replaced_count > 0,
        "auto_merge_replaced_chunks": replaced_count,
        "auto_merge_steps": int(merged_count_l3_l2 > 0) + int(merged_count_l2_l1 > 0),
        "post_merge_candidate_count": len(merged_docs),
    })
    return merged_docs, meta
```

###### 2-1-1）向父级 Chunk 合并

- 按 `parent_chunk_id` 分组，同一个 Parent 下命中数量达到阈值后，用 Parent Chunk 替换多个 Child Chunk。
- `_merge_rank_score_into`：对替换后的Parent Chunk的分数进行累积更新

```python
def _merge_to_parent_level(
    docs: List[dict],
    threshold: int = 2,
) -> Tuple[List[dict], int]:

    groups: Dict[str, List[dict]] = defaultdict(list)

    # 1. 根据 parent_chunk_id 对候选进行分组
    for doc in docs:
        parent_id = (
            doc.get("parent_chunk_id")
            or ""
        ).strip()

        if parent_id:
            groups[parent_id].append(doc)

    # 2. 找到命中数量达到阈值的 Parent
    merge_parent_ids = [
        parent_id
        for parent_id, children in groups.items()
        if len(children) >= threshold
    ]

    if not merge_parent_ids:
        return docs, 0

    # 3. 从 ParentChunkStore 查询对应父块
    parent_docs = (
        _parent_chunk_store
        .get_documents_by_ids(
            merge_parent_ids
        )
    )

    parent_map = {
        item.get("chunk_id", ""): item
        for item in parent_docs
        if item.get("chunk_id")
    }

    merged_docs: List[dict] = []
    parent_slot: Dict[str, int] = {}
    merged_count = 0

    # 4. 使用 Parent 替换多个 Child
    for doc in docs:
        parent_id = (
            doc.get("parent_chunk_id")
            or ""
        ).strip()

        # 没有对应 Parent 时保留原 Chunk
        if (
            not parent_id
            or parent_id not in parent_map
        ):
            merged_docs.append(doc)
            continue

        # 相同 Parent 已加入时，只合并分数
        if parent_id in parent_slot:
            existing = merged_docs[
                parent_slot[parent_id]
            ]

            _merge_rank_score_into(
                existing,
                doc,
            )

            merged_count += 1
            continue

        # 第一次遇到该 Parent，加入完整 Parent Chunk
        parent_doc = dict(
            parent_map[parent_id]
        )

        _merge_rank_score_into(
            parent_doc,
            doc,
        )

        parent_doc[
            "merged_from_children"
        ] = True

        parent_doc[
            "merged_child_count"
        ] = len(groups[parent_id])

        parent_slot[parent_id] = len(
            merged_docs
        )

        merged_docs.append(parent_doc)
        merged_count += 1

    return merged_docs, merged_count
```

###### 2-1-1-1）父块分数继承

- Auto-Merging 用父块替换多个子块后，需要给新的 Parent Chunk 继承一个检索分数。
1.  `_effective_score()` 先取得一个 Chunk 当前有效的分数，优先使用 `rerank_score`，没有时使用原始召回 `score`；（改函数可以给后面rerank之后来获取分数，当前父块合并，只有原始分数）
2. 打擂台让 Parent 保留所有子块中最高的分数。

```python
def _effective_score(
    doc: dict,
) -> Optional[float]:

    rerank_score = doc.get(
        "rerank_score"
    )

    if rerank_score is not None:
        return float(rerank_score)

    score = doc.get("score")

    if score is not None:
        return float(score)

    return None


def _merge_rank_score_into(
    target: dict,
    source: dict,
) -> None:

    incoming = _effective_score(source)

    if incoming is None:
        return

    uses_rerank = (
        source.get("rerank_score")
        is not None
        or target.get("rerank_score")
        is not None
    )

    # 已经存在 Rerank Score 时保留最大值
    if uses_rerank:
        existing = target.get(
            "rerank_score"
        )

        if existing is None:
            target["rerank_score"] = incoming
        else:
            target["rerank_score"] = max(
                float(existing),
                incoming,
            )

        return

    # 否则使用召回 score
    existing = target.get("score")

    if existing is None:
        target["score"] = incoming
    else:
        target["score"] = max(
            float(existing),
            incoming,
        )
```

##### 2-2）Rerank

- 调用外部 Rerank 服务重新计算 Query 和候选文档之间的相关度；调用失败时回退到原始分数排序。目前这里留作接口，供后续优化

```python
def _get_rerank_endpoint() -> str:
    # 获取rerank模型服务
    if not RERANK_BINDING_HOST:
        return ""
    host = RERANK_BINDING_HOST.strip().rstrip("/")
    return host if host.endswith("/v1/rerank") else f"{host}/v1/rerank"

def _rerank_documents(query: str, docs: List[dict], top_k: int) -> Tuple[List[dict], Dict[str, Any]]:
    # 排序前， rrf_rank只是父子合并之后的一个顺序，还没按score排序
    docs_with_rank = [{**doc, "rrf_rank": i} for i, doc in enumerate(docs, 1)]
    meta: Dict[str, Any] = {
        "rerank_enabled": RERANK_ENABLED,
        "rerank_applied": False,
        "rerank_model": RERANK_MODEL,
        "rerank_endpoint": _get_rerank_endpoint(), # 获取rerank服务地址
        "rerank_error": None,
        "rerank_timeout_seconds": RERANK_TIMEOUT_SECONDS,
        "candidate_count": len(docs_with_rank),
    }
    if not docs_with_rank or not meta["rerank_enabled"]:
        # 不做rerank，按照score排序
        return _sort_by_rank_score(docs_with_rank)[:top_k], meta

    # 1. 组装发送给 Rerank 服务的数据
    payload = {
        "model": RERANK_MODEL,
        "query": query, # 用户问题
        # 只把候选 Chunk 的文本发给 rerank 服务
        # docs_with_rank[0] 对应 documents[0]
        # docs_with_rank[1] 对应 documents[1]
        "documents": [doc.get("text", "") for doc in docs_with_rank],
        # 最多让 rerank 服务返回 top_k 条
        "top_n": min(top_k, len(docs_with_rank)),
        # 不需要服务把原文再返回，只需要 index + score
        "return_documents": False,
    }

    # 2. HTTP 请求头
    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {RERANK_API_KEY}",
    }
    try:
        # 标记：本轮确实尝试执行了 rerank
        meta["rerank_applied"] = True
        # 3. 调用外部 Rerank API
        response = requests.post(
            meta["rerank_endpoint"],
            headers=headers,
            json=payload,
            timeout=RERANK_TIMEOUT_SECONDS,
        )
        # Rerank 服务返回 4xx / 5xx
        # 不让整个检索失败，退回原来的 score 排序
        if response.status_code >= 400:
            meta["rerank_error"] = f"HTTP {response.status_code}: {response.text}"
            return _sort_by_rank_score(docs_with_rank)[:top_k], meta
        
        # 4. 读取 Rerank 服务返回结果
        items = response.json().get("results", [])
        reranked = []
        # 5. 将 relevance_score 写回文档
        for item in items:
            # index 表示这个结果对应原 documents 中的第几个文档
            idx = item.get("index")
            if isinstance(idx, int) and 0 <= idx < len(docs_with_rank):
                doc = dict(docs_with_rank[idx])
                score = item.get("relevance_score") # Rerank 模型重新计算出的相关性分数
                if score is not None:
                    doc["rerank_score"] = score # 把新的相关度分数写回文档
                reranked.append(doc)

        # Rerank 正常返回结果
        if reranked:
            return reranked[:top_k], meta
        
        # Rerank API 请求成功，但 results 是空的
        # 同样退回原 score 排序
        meta["rerank_error"] = "empty_rerank_results"
        return _sort_by_rank_score(docs_with_rank)[:top_k], meta
    except (requests.RequestException, json.JSONDecodeError, KeyError, ValueError, TypeError) as e:
        meta["rerank_error"] = str(e)
        return _sort_by_rank_score(docs_with_rank)[:top_k], meta


def _sort_by_rank_score(docs: List[dict]) -> List[dict]:
    return sorted(docs, key=lambda item: _effective_score(item) or 0.0, reverse=True)
```

### 2.1.3 RAG Pipeline 辅助函数
- 为 RAG Pipeline 提供检索结果后处理、检索过程记录以及检索不足时的 Query 重写能力。是执行了一次检索之后的一些操作。这部分几个函数预留后面使用，可以到下一个模块的时候来实现。
#### 1）文档去重
- 根据 `chunk_id` 去重，重复 Chunk 保留更高的相关度分数。预留，主要供后续 `RAG Pipeline` 的多子问题结果合成使用，将多个子 Agent 返回的检索结果按照 `chunk_id` 去重。

```python
def dedupe_documents(
    docs: List[dict],
) -> List[dict]:

    by_key: Dict[str, dict] = {}
    order: List[str] = []

    for item in docs:

        # 1. 优先使用 chunk_id 作为唯一标识
        chunk_id = (
            item.get("chunk_id")
            or ""
        ).strip()

        # 2. 没有 chunk_id 时使用来源信息兜底
        key = (
            chunk_id
            or
            f"{item.get('filename')}|"
            f"{item.get('page_number')}|"
            f"{item.get('text')}"
        )

        # 3. 第一次出现直接保存
        if key not in by_key:
            by_key[key] = item
            order.append(key)
            continue

        # 4. 重复项保留更高分数
        _merge_rank_score_into(
            by_key[key],
            item,
        )

    return [
        by_key[key]
        for key in order
    ]
```

#### 3）查询重写
- 根据用户问题自动选择 Step-back（把原问题“往后退一步”，从一个过于具体的问题抽象成更通用、更容易检索的问题。） 或 HyDE（让 LLM 根据问题生成一段“假设性的答案文档”，再拿这段更像知识库正文的文本去检索），并生成一次新的检索 Query。

```python
# 规定llm查询重写的输出结构
class RewritePlan(BaseModel):
    method: Literal["step_back", "hyde"] = Field(
        description="本轮唯一使用的查询重写方式"
    )
    step_back_question: str = Field(
        default="",
        max_length=300,
        description="仅在 method=step_back 时填写的抽象退步问题",
    )
    hyde_document: str = Field(
        default="",
        max_length=1200,
        description="仅在 method=hyde 时填写的假设性答案文档",
    )


REWRITE_PROMPT = (
    "你是 RAG 查询重写规划器。初次检索已经找到相关信号，但证据不足。"
    "请在 step_back 和 hyde 中只选择一种重写方式，并同时生成该方式需要的内容。\n\n"
    "选择规则：\n"
    "- step_back：原问题过于具体，包含实体名、型号、时间、条件或细节，"
    "需要提升到更概括的概念、机制或原理后再检索。\n"
    "- hyde：原问题模糊、概念性强、缺少知识库常用术语，"
    "适合先生成一段可能的答案式文档，再用这段文档检索真实证据。\n\n"
    "约束：\n"
    "- method=step_back 时，只填写 step_back_question，hyde_document 必须留空。\n"
    "- method=hyde 时，只填写 hyde_document，step_back_question 必须留空。\n"
    "- HyDE 文档只能用于检索，不代表真实证据，不要编造引用或来源。\n\n"
    "用户问题：{query}"
)


def _get_rewrite_model():
    global _rewrite_model
    if not ARK_API_KEY or not FAST_MODEL:
        return None
    if _rewrite_model is None: # 只有第一次调用时才创建模型
        _rewrite_model = init_chat_model(
            model=FAST_MODEL,
            model_provider=FAST_MODEL_PROVIDER,
            api_key=ARK_API_KEY,
            base_url=BASE_URL,
            temperature=0,
            stream_usage=True,
        )
    return _rewrite_model


def rewrite_query_once(query: str) -> dict:
    # 1. 获取快速模型
    model = _get_rewrite_model()
    if not model:
        raise RuntimeError("FAST_MODEL is required for query rewriting")

    # 2. 让模型选择 Step-back 或 HyDE
    result = with_structured_output(model, RewritePlan).invoke(
        [{"role": "user", "content": REWRITE_PROMPT.format(query=query)}]
    )
    method = result.method
    step_back_question = (result.step_back_question or "").strip()
    hyde_document = (result.hyde_document or "").strip()

    # 3. Step-back
    if method == "step_back":
        if not step_back_question or hyde_document:
            raise ValueError("Step-back rewrite plan must contain only step_back_question")
        rewritten_query = f"{query}\n\n退步问题：{step_back_question}"
    # 4. HyDE
    elif method == "hyde":
        if not hyde_document or step_back_question:
            raise ValueError("HyDE rewrite plan must contain only hyde_document")
        rewritten_query = f"{query}\n\n假设性答案文档：{hyde_document}"
    else:
        raise ValueError(f"Unsupported rewrite method: {method}")

    return {
        "rewrite_method": method,
        "rewritten_query": rewritten_query,
        "step_back_question": step_back_question,
        "hyde_document": hyde_document,
    }
```
