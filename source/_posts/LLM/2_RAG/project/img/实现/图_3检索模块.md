# 图_3检索模块

对应 [[3_代码实现_检索模块]]。输入查询，输出经过合并、重排和阈值过滤的证据及检索元数据。

### 主链如何衔接

`retrieve_documents()` → 候选数 → 共享模型编码 Query → Milvus L3 混合召回 → `_finalize_retrieval()` → Auto-Merging → Rerank Top-K → 分数过滤 → `{docs, meta}`。

Auto-Merging 只沿 `parent_chunk_id` 逐层查父块，不以 `root_chunk_id` 直接跳到 L1。父块缓存及数据库回查复用 [[图_1数据存储模块]]；查询向量复用 [[图_2文档入库模块]] 的 EmbeddingService。

### 需要区分的边界

- 当前函数负责找证据，不负责判断证据是否足以回答；后者由 [[图_4RAG工作流模块]] 的 Grader 完成。
- 改写预算由 Pipeline 控制。`rewrite_query_once()` 只执行一次改写调用，不自己决定是否重试。
- Rerank 未启用或失败时仍返回检索排序结果；成功选出 Top-K 后再过滤，最终证据数量可能少于 K。

验证示例见本篇 §3 标注的 `test/3_test_retrieval.py`（教程中的示例路径，不是仓库现有 tests 目录）。


### 图形约定

绿色是目录，蓝色是文件，紫色是类，橙色是函数；标题中的名称与职责之间保留 12 个空格。类框中的编号通常对应其方法；函数框的编号描述内部步骤。没有组合，矩形宽高可分别调整。
