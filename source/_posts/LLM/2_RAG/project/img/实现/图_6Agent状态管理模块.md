# 图_6Agent状态管理模块

对应 [[6_代码实现_Agent 状态管理]]。区分数据协议、单次请求状态、跨轮会话存储和 Agent 运行装配。

### 四块分别解决什么

1. `schemas/chat.py` 定义合法的数据形状：真实证据、主 / 子 Trace、HITL 恢复和 Chat 会话结果。字段详情留在原文章，不在图里重复列全表。
2. `ChatRequestContext` 隔离**一个请求**的工具预算、临时 Trace 和事件队列。Tool 写入，Service 读取；请求结束关闭。
3. `ConversationStorage` 维护**跨轮**消息与 metadata。PG 是持久化来源，Redis 缓存消息和列表；metadata 中的 pending_hitl 不依赖请求 ctx 存活。
4. `runtime.py` 持有共享模型，在每次请求中装配 Agent，并让知识工具绑定正确的 ctx。

### 重要实现取舍

`save()` 的真实实现是删除旧消息再重写完整历史，并非只追加一条新消息；会话 metadata 合并保存。`load_with_meta()` 即使消息缓存命中，也需要读取会话 metadata。原实现的 `user_id` 参数在存储层按 username 查用户，不能据参数名误画成整数用户主键。

### 与其他图的关系

[[图_7Agent对话编排模块]] 同时调用 Storage、ctx 和 Runtime；Runtime 装配 [[图_5工具层模块]]；Storage 下接 [[图_1数据存储模块]]。Pipeline 的 RAGState 定义仍在 [[图_4RAG工作流模块]]，不归本文件所有。


### 图形约定

绿色是目录，蓝色是文件，紫色是类，橙色是函数；标题中的名称与职责之间保留 12 个空格。类框中的编号通常对应其方法；函数框的编号描述内部步骤。没有组合，矩形宽高可分别调整。
