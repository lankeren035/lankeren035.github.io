# 图_12文档删除流程

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。请使用 Obsidian 的 Excalidraw 视图打开。

**所属模块：** M6 文档管理。总图与详图使用相同模块编号；画布右侧也包含以下读图说明。

### M6 组成

- 列表聚合 Milvus 叶子记录；上传衔接 M7 索引；删除清理多种存储。
- 同步在请求内完成；异步返回 job_id，进度由内存 JobManager 提供。
- 上传细节见图 03，下方展开删除分支。

### 清理顺序

- Milvus L3 → PG L1/L2 commit → Redis 父块缓存删除。
- BM25 统计由 Milvus 自动维护；没有独立重建任务。

### 边界

- 本地原文、聊天历史和已保存 Trace 保留。
- transactionally 是函数名，不代表跨库事务。
- 部分失败无自动回滚；Redis 异常可能被忽略。

### 源码对应

- `backend/api/routes/documents.py`：`delete_document_async()`
- `backend/api/routes/documents.py`：`_process_delete_job()`
- `backend/api/resources.py`：`delete_document_transactionally()`
- `backend/indexing/parent_chunk_store.py`：`delete_by_filename()`
- `backend/jobs/upload_jobs.py`：`UploadJobManager()`
