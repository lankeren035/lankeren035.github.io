# 图_15文档索引模块设计

原生 Excalidraw 可编辑画布，基于 SuperMew-0.1.0。

**视图类型：** M7 文档索引模块主图。上级为 [[图_1项目设计|系统总图]]。

### 模块边界

- 输入是 M6 已保存的 file_path 与 filename；鉴权、文件保存、同名清理和 job 属于 M6。
- M7 提供解析、三级分块、父块存取、叶子向量化与写入组件；原版没有独立 IndexingService。

### 真实调用

- DocumentLoader 按格式读取，再清洗文本、补充来源 metadata 并三级分块。
- M6 在 documents.py 中拆出 parent_docs / leaf_docs，先调用父块存储，再调用向量写入。
- MilvusWriter 初始化集合，按批调用 EmbeddingService，再组装字段并 insert。

### 存储与约束

- L1/L2 写入 PG，逐项缓存 Redis；L3 写入 Milvus。
- 本地模型只生成 dense；BM25 sparse 由 Milvus 的服务端函数生成。
- 父块 commit 后才开始叶子写入；中途失败没有统一跨库回滚。

### 关联视图

- 图 03 是上传任务的完整业务流程；图 08 是三级分块与跨库关联的数据契约。

### 关联视图

- [[图_3文档入库流程|图3：上传入库业务流程]]
- [[图_8三级分块与跨库关联|图8：分块与跨库数据契约]]

### 源码对应

- `backend/api/routes/documents.py`：upload_document / _process_upload_job：真实调用方与先父后叶顺序
- `backend/api/resources.py`：loader / parent_chunk_store / milvus_writer：组件实例装配
- `backend/indexing/document_loader.py`：DocumentLoader.load_document / sanitize_text / _split_page_to_three_levels
- `backend/indexing/html_processor.py`：load_html_for_document_loader：HTML 解析与章节页
- `backend/indexing/parent_chunk_store.py`：ParentChunkStore.upsert_documents：父块 PG 与 Redis
- `backend/indexing/milvus_writer.py`：MilvusWriter.write_documents：叶子批处理、字段组装、进度
- `backend/indexing/embedding.py`：EmbeddingService.get_embeddings：本地 dense
- `backend/indexing/milvus_client.py`：MilvusStore.ensure_collection / init_collection / insert：Schema、BM25 与写入
